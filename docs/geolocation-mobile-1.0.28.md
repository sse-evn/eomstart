# Мобильная геолокация: 1.0.28+2

Изменения подготовлены 10 сентября 2026 года. Этот выпуск предназначен для
работы с существующим Go API. Обновлять сервер или применять миграции сервера
для установки приложения не требуется. APK/IPA этого выпуска ещё не собраны.

## Что исправлено

- Временная ошибка проверки смены сохраняет последнее известное состояние.
  При запуске без интернета отсутствие ответа не отменяет сохранённую смену.
  Ручной перезапуск GPS также использует сохранённую смену при недоступном API.
- На Android проверяется отклик обработчика, его смена и состояние цикла.
  Если нативный сервис запущен, но обработчик устарел, выполняется восстановление.
  Если ответа нет, приложение показывает проблему, а не успешный запуск GPS.
  Перед запуском проверяются GPS и разрешение: это учитывает
  [требования Android к сервису location](https://developer.android.com/develop/background-work/services/fgs/service-types#location).
- На iOS поток Core Location работает на основном Flutter engine, с разрешёнными
  фоновыми обновлениями. Старый флаг SharedPreferences не препятствует запуску.
  Сохранённые токены переводятся в Keychain first_unlock для доступа при блокировке.
- Сбор и отправка независимы. Пока HTTP-запрос ждёт ответа, новые измерения
  продолжают сохраняться в SQLite. Старые ответы GPS не заменяют более новые точки.
- Очередь разделена по сотрудникам, переживает перезапуск приложения и обновление
  формата базы. Накопленные данные не удаляются целиком при частичном подтверждении.
  Явно отклонённые сервером записи сохраняются локально с отметкой rejected_at.
- Зависший HTTP-запрос ограничен по времени; его соединение закрывается перед
  повторной попыткой. При сбоях задержка повторов растёт до двух минут; восстановление
  сети снимает задержку. Смена аккаунта не переносит точки в чужую смену.
- Фоновое обновление токена не удаляет вход пользователя. Запоздалый ответ
  обновления токена не перезаписывает более новую авторизацию.
- Через существующий /api/shifts/active примерно раз в две минуты проверяется,
  остаётся ли смена открытой. Ошибка запроса сохраняет сбор; подтверждённое завершение
  останавливает его. Эта проверка не блокирует запись координат.
- При выключенном GPS, недостаточных разрешениях, проблеме записи или доставки
  показывается предупреждение. Рабочие действия не блокируются, смена не закрывается
  из-за отключения GPS. На Android есть предупреждение об ограничениях батареи
  с переходом к системному запросу разрешения.

## Совместимость с текущим сервером

Адрес и формат запроса сохранены: POST /api/geo, JSON с массивом data, Bearer token.
point_id и tracking являются дополнительными полями; прежний Go-обработчик их
игнорирует. Передаётся до 100 точек за запрос, включая свежую точку при наличии
большой очереди. Это также укладывается в лимит 1000 точек из локальной версии Go.

Старый ответ points_saved подтверждает пакет только при совпадении с количеством
отправленных точек. Частичный ответ не позволяет узнать, какие именно точки записаны:
пакет остаётся для повторной отправки. Прежний сервер не устраняет дубликаты, поэтому
при потерянном или частичном ответе повторные записи на сервере всё ещё возможны.

Пустой успешный ответ на служебное сообщение не считается передачей свежей координаты.
Дополнительные статусы для руководителя появятся только после отдельного обновления
Go. Этот мобильный выпуск не меняет серверное хранение времени: если сервер подменяет
время измерения временем приёма, исправить историю только приложением нельзя.

## Проверки

Результат 10 сентября: все 49 тестов прошли три последовательных прогона с разным
порядком выполнения. Оба теста настоящей SQLite прошли. Полный анализ Flutter:
0 ошибок, 31 существовавшее предупреждение. Нативные APK/IPA не собирались.

Проверяется пакет test/geo: 49 тестов, включая сохранение при медленном HTTP на обеих
платформах, повторные ошибки GPS-потока, смену аккаунта, устаревший ответ измерения,
отзыв разрешения, восстановление обработчика, закрытие смены, частичные ответы и
двухчасовую симуляцию работы с отключениями сети и разрешений.

В tool/geo_queue_check проверяется настоящая SQLite: два теста, включая переход с
первой версии очереди и сохранение отклонённых данных после повторного открытия.
Это локальные проверки; они не отправляют координаты на рабочий сервер.

Команды для повторения:

```sh
flutter pub get
flutter test --no-pub test/geo
flutter analyze --no-pub
```

Для отдельной проверки SQLite выполнить flutter pub get и flutter test test в
каталоге tool/geo_queue_check. Полный анализ проекта пока сообщает о прежних
предупреждениях и замечаниях стиля; отсутствие ошибок компиляции не означает
нулевой код завершения команды анализа.

## Сборка и проверка на телефонах

В pubspec.yaml выставлена версия 1.0.28+2. Существующий тестовый APK от 6 сентября
не содержит этот выпуск. Для Android используется flutter build apk --release;
для iOS — flutter build ipa --release на macOS с настроенной подписью.
Скрипты публикации для сборки запускать не нужно.

Перед массовой установкой проверить на iPhone и vivo:

1. Обновить приложение поверх установленного, открыть его и проверить разрешения.
2. Открыть смену, пройти 30–60 минут с заблокированным экраном; проверить свежесть GPS.
3. Три раза отключить и включить GPS; предупреждение должно появляться и уходить.
4. Отключить интернет на 10 минут, затем включить: накопленное должно отправиться.
5. Вернуться в приложение после длительного фона и проверить восстановление.
6. Закрыть смену, в том числе при накопленной очереди: новые точки не должны собираться.

Двухчасовой тест — симуляция времени, не испытание телефона с заблокированным экраном.
Физических Android/iPhone и Xcode в этой среде нет. Проверка XML/plist не заменяет
нативную сборку и испытания устройств. После принудительного завершения приложения
на iPhone непрерывный сбор стандартным Core Location не гарантируется:
[ограничение Apple](https://developer.apple.com/documentation/corelocation/cllocationmanager/startupdatinglocation()).

Если координаты не измерялись, приложение и сервер не смогут восстановить
пропущенный участок маршрута. Если измерения успели сохраниться в SQLite, очередь
сохранит их для последующей доставки.
