# Геолокация открытой смены: изменения и проверка

Это отчёт о совместных локальных изменениях Flutter и Go от 6 сентября.
Актуальный выпуск только приложения описан в [1.0.28+2](geolocation-mobile-1.0.28.md).
Описанные ниже дополнительные серверные статусы не включаются одним обновлением приложения.

## Поведение

Рабочие действия не блокируются. Отключение GPS не закрывает смену, не меняет оплату и само по себе не считается доказательством нарушения.

- На телефоне отображается постоянное, но неблокирующее предупреждение: GPS выключен, нет разрешения, нет свежей координаты, низкая точность или нет связи с сервером.
- На карте руководителя состояния GPS/разрешений подтверждаются тремя наблюдениями. Сервер засчитывает наблюдения с интервалом минимум 20 секунд, а подтверждение — не раньше 40 секунд. Телефон отправляет состояние примерно раз в 30 секунд.
- Нет координат или последняя точка старше трёх минут — отдельное состояние отсутствия свежих данных. Оно не утверждает, что сотрудник намеренно отключил GPS.
- Сотрудник без координат остаётся в списке руководителя; маркер без позиции не рисуется.
- Существующая Telegram-сводка использует эти же подтверждённые статусы. Её расписание не изменено; дополнительных рассылок при разработке не выполнялось.
- Временные ошибки API не означают закрытие смены и не удаляют авторизацию. Подтверждённая закрытая смена останавливает сбор.

## Передача и хранение

Android использует foreground service с типом location. iOS использует поток Core Location на основном Flutter engine; таймер не является гарантией фоновой работы. При возвращении приложения проверяются разрешения и работа службы. Сохранённый флаг прошлого процесса не считается доказательством работающего трекера.

Точка принимается приложением только с исходным временем измерения, возрастом до 60 секунд и точностью до 100 метров. Повторная старая позиция не получает новое время. Между сохранениями — примерно 15 секунд. Права и GPS не включаются в обход решения пользователя.

Точки записываются в SQLite до отправки. Очередь разделена по сотрудникам; удаляются только подтверждённые идентификаторы. Пакет содержит до 100 точек, включая самую свежую, чтобы накопленная история не задерживала текущую позицию. Непереданные точки сохраняются и после завершения смены для последующей отправки с авторизацией того же сотрудника.

Бэкенд сохраняет recorded_at (измерение), created_at (приём), shift_id и point_id. Повторная доставка не создаёт дубликаты. Проверяется принадлежность смены сотруднику и время точки относительно смены. Для границ смены допускается расхождение часов до двух минут. Принимаются отложенные точки закрытых смен возрастом до семи дней; более старые или некорректные точки отклоняются с явным подтверждением отклонения. Сбой Redis не отменяет уже сохранённую точку.

На iOS существующие токены переводятся в режим Keychain first_unlock, чтобы они были доступны после блокировки экрана, начиная с первого разблокирования после перезагрузки.

## Порядок выпуска

1. Сначала обновить бэкенд. Дополняющая миграция `db/migrations/008_geo_tracking.sql` встроена в запуск. Старые строки не перезаписываются; для них остаётся прежнее время приёма. Их фактическое время измерения восстановить из имеющихся данных нельзя.
2. Затем выпустить приложение. Старые версии приложения совместимы с новым API, однако продолжают присылать собственные старые временные метки.
3. До массового выпуска выполнить проверки на нескольких реальных моделях Android и iPhone.

Продакшен при этой работе не обновлялся. Основной сервер не запускался для тестов: у него есть фоновые задания и интеграции.

## Автоматические проверки

- Flutter: `flutter test --no-pub test/geo` — отключение/включение GPS, отзыв разрешения, устаревшие координаты, плохая точность, отключённая сеть, частичные ответы, повторные запросы, смена аккаунта, обновление токенов, неблокирующее предупреждение.
- Go: `go test ./internal/... ./cmd/server/... ./db/...`.
- PostgreSQL: `EOM_TEST_DATABASE_URL=... go test -race -count=3 ./internal/services/geo ./internal/handlers/geo ./db` с отдельной временной базой. Тесты создают отдельную схему, не запускают сервер, не отправляют сообщения. Проверяются миграция, история с исходным временем, повторная доставка, чужая/закрытая смена, отсутствие координат, подтверждение проблемы и восстановление.
- Flutter analysis: сравнение с исходным состоянием; исходно были 31 предупреждение и многочисленные рекомендации стиля.

## Что обязательно проверить на устройствах

| Сценарий | Ожидаемый результат |
|---|---|
| Открыть смену и пройти 10 минут с включённым экраном | Координаты движутся, нет повторной старой точки с новым временем |
| Идти 20 минут с заблокированным экраном | Новые измерения продолжают приходить; отдельно проверить Android разных производителей и iPhone |
| Три раза отключить GPS на 90 секунд и включить обратно | Предупреждение без блокировки действий, подтверждение у руководителя, восстановление координат |
| Отозвать разрешение, затем вернуть его | Корректная причина предупреждения, восстановление после возврата в приложение |
| Отключить интернет на 10 минут, затем вернуть | Точки сохранены, текущая позиция поступает вместе с историей, время маршрута не сдвигается |
| Оставить телефон неподвижным | Не появляется ложный статус отключённого GPS только из-за отсутствия перемещения |
| Закрыть смену при наличии очереди | Новые точки больше не собираются, накопленные могут быть доставлены позже |
| Завершить процесс, перезагрузить телефон, открыть приложение | Трекинг восстанавливается после проверки смены и разрешений, а не по старому флагу |

Подключённых Android/iPhone при разработке не было. iOS-сборка требует macOS/Xcode. Автотесты не заменяют испытания радиомодуля, энергосбережения и системного завершения приложения.

Ограничения платформ: [Apple — стандартные обновления геолокации](https://developer.apple.com/documentation/corelocation/cllocationmanager/startupdatinglocation()) прекращаются при завершении процесса; [flutter_background_service](https://pub.dev/packages/flutter_background_service) не обеспечивает постоянный таймер iOS через background fetch. [Keychain first_unlock](https://pub.dev/packages/flutter_secure_storage) допускает фоновое чтение после первого разблокирования. Поэтому отсутствие сигнала отображается как проблема связи/геолокации, а не как доказательство умышленного отключения.
